The Upstream Failure Mode
02 / 08
Failure State

Network drops are inevitable. Double charges are not.

When a core banking switch drops an ISO 8583 acknowledgement or an SMS OTP times out, naive payment systems write double balances or trigger aggressive mobile client retries.

// The Failure State:
1. Client sends checkout request.
2. Banking switch approves hold.
3. Webhook drops due to 504 Gateway Timeout.
4. Client retries → Balance debited twice.

Ingress Rule 1
03 / 08
Locking Architecture

Distributed Idempotency Locks

Every checkout request must carry a unique client UUID, locked at the ingress gateway using Redis SETNX before reaching internal services.

key = "idemp:" + request.uuid
acquired = redis.set(key, "LOCKED", nx=True, ex=30)
if not acquired:
  return HTTP 409 Conflict ("In-Flight Transaction")

Ingress Rule 2
04 / 08
Timeout Handling

Asynchronous State Fallbacks

Never let mobile clients hang waiting on third-party banking switches. If an upstream host takes over 3,500ms, cut the connection and queue automated resolution.

// Fast-Fail Invariant:
- Threshold: 3,500ms max switch wait.
- Action: Return pending status to app.
- Background: Queue automated inquiry query.
- Outcome: Zero blocked user threads.

Ingress Rule 3
05 / 08
Dynamic Routing

Automated Circuit Breakers

When an upstream acquirer error rate exceeds 2% over a 60-second sliding window, dynamically divert traffic to backup rails in under 200ms.

if acquirer.error_rate_60s() > 0.02:
  circuit.trip(acquirer_id)
  traffic.reroute(backup_psp_switch)
  telemetry.alert("PSP Switch Diverted")
